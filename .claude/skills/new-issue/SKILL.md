# 新しい号を作る

CLAUDE.md のルール（触ってよいのは `src/content/issues/` と `media/` だけ、Public リポジトリ、本番操作はしない）を守って進める。
各ステップの終わりで、人に結果を見せてから次へ進む。

## 1. 材料を確かめる

次の4つがそろっているか確認する。足りないもの・あいまいなものは、推測せずに聞く。

- [ ] 号ID（原則 `年-月`。例：`2027-01`）。`src/content/issues/` に同じIDがないこと
- [ ] 公開日時（日本時間）。`2027-01-01T10:00:00+09:00` の形にして、人に復唱して確かめる
- [ ] 原稿（タイトル、説明文160字以内、本文、見出し、ボタンの文言とリンク先）
- [ ] 素材（画像・動画のファイルと、それぞれの用途。代替テキストに書く内容）

原稿や素材に、実在の企業名・ブランド名・人名・個人情報・秘密情報が含まれていたら、そのまま使わずに人に知らせる。

## 2. ブランチを作る

```
git switch main
git pull
git switch -c issue/<号ID>
```

作業ツリーに関係のない変更が残っていたら、先に人に確認する。

## 3. 素材を置く

- `media/<号ID>/` を作り、素材を置く
- ファイル名を英小文字・数字・`_`・`-` にする（例：`hero.jpg`、`look-01.jpg`、`item-01.jpg`）。元のファイル名との対応を人に見せる
- 動画は変換してから置く：`npm run media:video -- <原本> media/<号ID>/<名前>.mp4`
- 背景動画には、必ずポスター画像（動画の代わりに表示する静止画）を用意する。なければ人に頼む
- 1ファイル25MB以上のものは置かない

## 4. 構成案を作り、確認をとる

内容ファイルを書く前に、ブロックの並びを箇条書きで人に見せる。例：

```
1. hero：ポスター hero.jpg ／ 動画 hero.mp4 ／ 見出し「冬の贈りもの」／ 小見出し Holiday Collection
2. heading：贈ることの喜び
3. text：2段落
4. section（背景動画 snow.mp4、ポスター snow.jpg）：見出し＋本文
5. reveal（slide-left）：画像 gift.jpg ＋ ボタン「ギフトを選ぶ」→ /issues/2027-01/
```

- 使えるブロックと項目は CLAUDE.md の「使えるブロック」に従う。表現できない要望は「エンジニアへの依頼」として分けて伝え、今ある部品での代案を出す
- 原稿の文言は勝手に書き換えない。表記ゆれや長すぎる箇所は、修正案として示す

## 5. 内容ファイルを書く

- `src/content/issues/<号ID>.json` を作る。`"id"` はファイル名と同じにする
- 見本：`src/content/issues/2026-11.json`
- `alt`・`posterAlt` は、画像の内容が伝わる文にする

## 6. 確かめる

```
npm run check
npm test
```

- 失敗したら、エラーメッセージに従って内容ファイルか素材を直す（CLAUDE.md の「よくあるエラー」）
- 内容ファイル・素材以外を直さないと通らない場合は、作業を止めて人に伝える

通ったら、人に `npm run dev` で開いてもらい、次を確認してもらう。

- `http://localhost:4321/issues/<号ID>/` の表示（スマホ幅でも）
- 文言・画像・リンク先
- 公開日時（ページ左下の「未公開の号です」の表示に出る）

## 7. PR を出す（人の了承を得てから）

push と PR の作成は外部に公開する操作なので、実行前に必ず人に確認する。

```
git add src/content/issues/<号ID>.json media/<号ID>/
git status   # 内容ファイルと素材以外が入っていないこと
git commit -m "<号ID>号を追加（公開：<公開日時>）"
git push -u origin issue/<号ID>
gh pr create --base main --title "<号ID>号を追加" --body "<下の本文>"
```

PR の本文：

```
## 内容
- 号ID：<号ID>
- タイトル：<タイトル>
- 公開日時：<公開日時（日本時間）>

## 確認してほしいこと
- <文言・画像・リンク先など>

## プレビュー
Actions の「Preview (PR)」の実行結果（Summary）にURLが出ます。
```

`gh` が使えない場合は、push までにして、GitHub の画面で PR を作るよう人に案内する。

## 8. 後のこと

- プレビューURLは、Actions の「Preview (PR)」の Summary に出る。確認する人に伝えてもらう
- 修正の依頼が来たら、同じブランチで直して push する（プレビューも更新される）
- マージは承認者が行う。Claude Code はマージしない
